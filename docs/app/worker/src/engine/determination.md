# `app/worker/src/engine/determination.ts`

A line-for-line port of steps 1-5 of `src/determination.py`: the Form 433-A(OIC) screening math and the expense and equity calculation-trace steps. Step 6 (the `Determination` record and the decision tree) is in `resolution-path.ts`. The module is pure (no I/O, no clock, no network); standards come from the injected `StandardsRepository`. Python stays the oracle: `parity.test.ts` proves every output equal to `golden.json`, which `src/tools/export_golden_fixtures.py` produces from the unchanged Python.

**Never change a constant, threshold, formula or wording here without changing Python first** (with an authoritative source and tests), then regenerating the fixtures.

| `calculateAllowableExpenses(fd, repo, trace?)` | `calculate_allowable_expenses` (:38-115) | Box E. Counts people 65+ (age 65 is the health-care split) and derives people under 65 (may go negative, ported as is). Looks up the transportation area only when `vehicle_count` is truthy (else `''`). Then looks up every standard before building `allowed`, in Python's order: national, housing, ownership, operating, health care for age 30 and then age 65 (both lookups always happen). Allowed amounts: national standard (line 39, always the standard); lesser of actual and standard for housing (40), ownership (41) and operating (42); public transportation only with no vehicle (43); health insurance actual (44); out-of-pocket health care always the standard (45); the six actual-only lines (46-51 and other secured debts). `total = sumInOrder(...)` as Python `sum()`. With a `trace` array it appends the food step, the three capped steps (inputs `Actual` and `IRS standard`), the eight actual-only steps (formula `Actual allowed amount`, or `Actual amount when no vehicle is owned` for public transportation), and then inserts the out-of-pocket health-care step at index 5 (`trace.insert(5, …)` in Python, `splice(5, 0, …)` here). |
| `calculateNetDisposableIncome(fd, repo)` | `calculate_net_disposable_income` (:121-125) | Box F: income minus the allowable total. |
| `NRE_LINE_KEYS`, `NreLines`, `NRE_LINE_LABELS` | — | The seven Section 3 lines in the order Python adds them, and short display labels naming each 433-A(OIC) line and its rule (reserve, ×0.8, exemption, deduction). Used by the staff view and worksheet so neither re-implements the math. |
| `netRealizableEquityLines(fd, trace?)` | `calculate_net_realizable_equity` body (:132-193) | Each term exactly as Python: cash less the $1,000 reserve (line 1); investments (2); retirement ×0.8 less loan (3); life-insurance cash value less loan (4); real property ×0.8 less loan (5); vehicles (6); other assets ×0.8 less loan less the $11,980 deduction (7). Vehicles use the per-vehicle list when it is non-empty: ×0.8 less that vehicle's loan, a missing loan counts as 0, and the $3,450 exemption applies to the first vehicle and to the second when `filing_joint_offer`. Otherwise the legacy totals apply, with $3,450 per exempt vehicle (1, or 2 for a joint offer, capped at `vehicle_count`) and one `Vehicles` step. Every `max`/`min` is `pyMax`/`pyMin`. With a `trace` array it appends the cash, investments, retirement, life insurance and real property steps, then the vehicle steps, then other valuable assets, with Python's labels, formulas, inputs and input keys. |
| `calculateNetRealizableEquity(fd, trace?)` | `total = …` (:171) | `cash + investments + retirement + life_insurance + real_property + vehicles + other_assets`, the same chain as Python, from `netRealizableEquityLines` (which receives the trace). |
| `passesComplianceGate(fd)` | `passes_compliance_gate` (:199-207) | The two Section 9 gates: unfiled returns and open bankruptcy, with Python's reason strings. Returns `[ok, reasons]`. |

## Rules

- Constants stay inline where Python has them (`1000`, `0.8`, `3450`, `11980`, ages `30`/`65`), each with a comment naming the Python line and the form line (D-02).
- The trace argument is optional and only appends; calling without it gives the same numbers (the breakdown parity test does exactly that).
- No JS built-in max/min, no `Date`, no `fetch`, no Hono/Supabase import (purity block in `parity.test.ts`).
