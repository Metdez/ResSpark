# `app/worker/src/index.ts`

The single Worker (D-01): a Hono app for `/api/*`, `/webhooks/*`, and `/c/*`, plus the `queue` and `scheduled` handlers. Exports `app` for `app.request()` tests and the default `ExportedHandler`.

| Lines | What it does |
|-------|--------------|
| 1-21 | Hono, `createMiddleware`, `HTTPException`, `requestId` middleware and its `RequestIdVariables` type, `secureHeaders`, the cron handler `scheduled` (Phase 4, `cron.ts`), the queue consumer `queue` and its `Job` type (Phase 4, `jobs/index.ts`), the allowlisted logger, the `StaffCtx` type (owned by `middleware/staff-auth.ts`), the admin integrations route, the admin lookup route, the two request routes (actions and CRUD), the admin session route, the staff review and case-events routes (Plan 03-03, `admin-review.ts`, `admin-events.ts`), the client upload route (Plan 03-01), the client-link route, the client-portal route, the config route, and the webhook route (Phase 4, `routes/webhooks.ts`). |
| 23-26 | `app` typed with `Bindings: Env` (from `worker-configuration.d.ts`) and the context variables `requestId`, optional `staff`, optional `errorCode`. |
| 28-29 | Every request gets a request id, then the logger (runs last on the way out, so it sees the final status). |
| 30 | `secureHeaders()` on `/api/*` (`Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, …). |
| 31-38 | `clientPrivacyHeaders` sets `Cache-Control: no-store` and `X-Robots-Tag: noindex`. It runs on `/c/*` (after `secureHeaders()`) and on `/api/c/*` (which already has `secureHeaders()` from `/api/*`, so `Referrer-Policy: no-referrer` too), so every client-portal response, 401/403/429 included, is private (D-13). They are set **after** `next()` on `c.res`: Hono only materialises headers prepared before `next()` when the handler builds its response through `c.json`/`c.body`; a raw `Response` (the asset fallback) would drop them. |
| 40-50 | Error envelope `{ error: { code, message } }`. `HTTPException` → its status, `code` = its message (`'unauthorized'`, `'forbidden'`…); anything else → 500 `internal` / "Something went wrong". `errorCode` is stored for the logger; stack traces and messages of unknown errors are never serialised (T-01-10). |
| 52-64 | Mounts `GET /api/config`, `GET`/`POST /api/admin/session` (Plan 06; guarded by `staffAuth` inside the route), the Phase 2 Logics credentials route at `/api/admin/integrations` (`GET`/`PUT /logics`, `POST /logics/test`), the request routes at `/api/admin/requests` (`admin-requests.ts` first: `GET /templates`, `POST /`, `GET /`, `GET /:id`; then `admin-request-actions.ts`: `POST /:id/send` and the other actions; Hono composes both under one prefix, and `staffAuth` verifies once because it skips when `staff` is already set), the staff review routes at `/api/admin` (Plan 03-03, `routes/admin-review.ts`: `GET /requests/:id/review`, `GET /documents/:id/url`, `POST /items/:itemId/approve`, `POST /items/:itemId/reject`) and the case events route (`routes/admin-events.ts`: `GET /cases/:id/events`), then the Phase 5 Logics push routes (Plan 05-01, `routes/admin-logics-push.ts`: `POST /requests/:id/logics-push`, `GET /requests/:id/logics-pushes`, `POST /logics-pushes/:pushId/resolve`; its `staffAuth` is scoped to `/requests/*` and `/logics-pushes/*`), then the Phase 4 staff connection routes (`routes/admin-connections.ts`: `GET /requests/:id/connections`, `POST /connections/:id/refresh`, `GET /connections/:id/transactions`; its `staffAuth` is scoped to those paths), all before the lookup mount so it stays last, the Phase 2 lookup route at `/api/admin` (`POST /lookup`, `POST /cases/:logicsCaseId/confirm`, `GET /cases/:id`), `GET /c/:token` (Plan 07, `routes/client-link.ts`), which sits behind the `/c/*` headers middleware, and the client portal at `/api/c` (Plan 02-07, `routes/client-portal.ts`: `GET /state`, `POST /start`, `POST /heartbeat`, cookie session only), followed by the client upload routes on the same prefix (Plan 03-01, `routes/c-uploads.ts`: `POST /items/:itemId/uploads`, `POST /uploads/:documentId/complete`, `POST /uploads/:documentId/token`, `GET /items/:itemId/documents`), which the same `/api/c/*` privacy headers cover, then the client connection routes (Plan 04-03, `routes/c-connections.ts`: `GET /items/:itemId/connection`, `POST /consents`, `POST /connections/:kind/start`, `POST /connections/:id/reconcile`), and finally `POST /api/webhooks/:provider` (Phase 4, `routes/webhooks.ts`: raw-body signature check, idempotent ledger insert, enqueue). Order does not matter between `/api/c` and the admin prefixes because they are distinct. The lookup route is the last `/api/admin` mount on purpose: its `use('*', staffAuth)` matches every `/api/admin/*` path, so if it were mounted earlier it would verify the token a second time on sibling admin routes. Mounted last, a sibling's handler answers first. An unknown `/api/admin/*` path therefore needs a valid token before it gets 404. |
| 42 | `app.use('/c/*', clientCsp)` (Plan 04-03, `middleware/client-csp.ts`): the Content-Security-Policy that lets Truv Bridge and Plaid Link load on the client portal. Set after `next()`, so the SPA fallback and the invalid-link page carry it; `/admin/*` and `/api/*` get no CSP change. |
| 66-76 | `notFound`: `/api/*` and `/webhooks/*` get 404 JSON `not_found` (never `index.html` with 200, T-01-12); every other path (e.g. `/c/`, which `/c/:token` does not match because the param cannot be empty) falls back to the SPA via `env.ASSETS.fetch`. The asset response is cloned (`new Response(res.body, res)`) because fetched responses have immutable headers and the `/c/*` middleware must add headers. The path is read for routing only. |
| 78-82 | Default export: `fetch` from Hono; `queue` is the Phase 4 consumer from `jobs/index.ts` (webhook and reconcile jobs, retry with backoff, DLQ); `scheduled` is `cron.ts` (Phase 4: the 15-minute reconciler and the 03:00 daily removal dispatch, branching on `controller.cron`). `satisfies ExportedHandler<Env, Job>` types the queue body as `Job`. |

## Notes

- Middleware order matters: `requestId` → `logger` → scoped `secureHeaders` → routes. The logger reads `routePath(c, -1)` after the chain completes.
- No `console.*` here; the logger owns the request log line and `jobs/index.ts` the job log line (ESLint `no-console: error`, disabled on those lines only).
- `/admin` never reaches this Worker: it is not in `run_worker_first`, so assets serve it directly.

## Tests

- `app/worker/test/connections-tracer.test.ts` (live) drives `/api/webhooks/truv` and the `queue` export end to end; `app/worker/src/routes/webhooks.test.ts` covers the route's failure paths.

- `app/worker/test/admin-integrations.test.ts` covers the Logics credentials routes.
- `app/worker/test/admin-requests.test.ts` and `app/worker/test/admin-request-actions.test.ts` cover the request routes.
- `app/worker/test/uploads.test.ts` (live) and `app/worker/src/routes/c-uploads.test.ts` cover the upload routes.
- `app/worker/test/client-portal.test.ts` covers `/api/c/*`, including the privacy headers on its error responses; `app/worker/test/client-link.test.ts` covers the same headers on `/c/*`.
- `app/worker/test/auth.test.ts` covers the session route's 401/403/400 paths and the logged `error_code`.
- `app/worker/test/config.test.ts` (Task 2) drives `app.request()` with a mock `Env` for `/api/config`, the 404 envelope, and the `/c/` fallback headers.
