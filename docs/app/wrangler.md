# `app/wrangler.jsonc`

Input config for the `resspark` Worker (D-06). `vite build` (via `@cloudflare/vite-plugin`) reads it and writes the deployable output `dist/resspark/wrangler.json`; `wrangler deploy` picks that up automatically. Re-run `pnpm -C app cf-typegen` after any change so `worker-configuration.d.ts` stays in sync.

| Key | What it does |
|-----|--------------|
| `$schema` | Editor validation from the installed wrangler's schema. |
| `name` | Worker name `resspark`; with the free subdomain this yields `https://resspark.zh-a16.workers.dev`. |
| `account_id` | The Cloudflare account ("Zh@licom.ai's Account", Workers Paid). |
| `main` | Worker entry `./worker/src/index.ts` (Hono app + `queue` + `scheduled`). |
| `compatibility_date` / `compatibility_flags` | `2026-10-10` runtime, `nodejs_compat` for `node:` builtins (Buffer, crypto helpers later). |
| `assets.binding` | Exposes the static-asset store as `env.ASSETS`; without it `wrangler types` emits no `ASSETS` member and the SPA fallback in `index.ts` cannot compile. |
| `assets.not_found_handling` | `single-page-application`: unknown paths that reach the asset layer get `index.html` with 200. |
| `assets.run_worker_first` | `/api/*`, `/webhooks/*`, `/c/*` hit the Worker before assets; everything else (e.g. `/admin`) is served straight from assets. `directory` is deliberately omitted because the Vite plugin supplies the client build. |
| `vars` | Demo-safety flags (D-19): `APP_ENV=sandbox`, `LOGICS_WRITE_ENABLED=false`, `LOGICS_TEST_CASE_IDS=""` (Phase 5 D-10: these two guard Logics writes in `live` mode only; fake-mode pushes skip them. Flip them only by following `logics-live-switch.md`). Phase 2 adds `LOGICS_MODE=fake` (fixture Logics cases; set it to `live` only after Settings → Integrations → Test connection succeeds, C1) and `EMAIL_FROM=""` (sender address for all email through Cloudflare Email Service; empty means email is off and reports `not_configured`; set it to an address on a domain onboarded under Compute → Email Service → Email Sending). Phase 4 (D-15) adds `PLAID_ENV=sandbox`, `TRUV_TEMPLATE_ID=""` (optional Truv order template id; empty means orders are built inline), `PLAID_REMOVE_AFTER_DAYS=30` (how long after connecting a Plaid Item is removed, BANK-06), and `BANK_PROVIDER=plaid` (`teller` once that adapter exists). Phase 6 (D-10) adds `DOCUSEAL_API_URL=https://api.docuseal.com` (the DocuSeal API base) and `DOCUSEAL_ENV=test` (Test Mode until production keys exist). Plain strings; `cf-typegen` runs with `--strict-vars=false` so they type as `string`, not the literal `"false"`. |
| `secrets.required` | `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `CLIENT_LINK_HMAC_KEY` (D-07, Plan 05), `INTEGRATION_ENC_KEY` (Phase 2, D-01: the AES-GCM key that seals `firm_integrations` credentials), and `TOKEN_ENC_KEY_1` (Phase 4, D-15: the key that seals Plaid access tokens in `connection_secrets`). The vendor keys `PLAID_CLIENT_ID`, `PLAID_SECRET`, `TRUV_CLIENT_ID`, and `TRUV_SECRET` are deliberately not listed: without them the Worker still deploys, `/start` answers `provider_not_configured`, and the portal shows the manual-upload fallback. They are typed as optional in `worker/src/provider-env.d.ts` and set with `pnpm -C app secrets:provider plaid|truv`. The Phase 6 keys `DOCUSEAL_API_KEY`, `DOCUSEAL_WEBHOOK_SECRET`, `SMARTY_AUTH_ID`, and `SMARTY_AUTH_TOKEN` are also left out on purpose (D-10, D-06): without the Smarty pair the address routes answer `provider_not_configured` and the client types the address by hand; without the DocuSeal pair e-sign stays unavailable. Set them with `pnpm -C app secrets:provider docuseal|smarty`. Email needs no secret: it uses the `send_email` binding. `wrangler deploy` refuses to deploy if any is not set on the Worker, and `cf-typegen` adds them to `Env` as `string`. Values are set by `app/scripts/provision-secrets.mjs`; locally they come from git-ignored `app/.dev.vars`. |
| `ratelimits` | `LINK_RATE_LIMITER` (namespace `1001`, 20 requests per 60 s), the Workers Rate Limiting binding used by `worker/src/middleware/link-rate-limit.ts` to throttle `/c/:token` per client IP (D-18). Counters are per Cloudflare location. Deploy accepted it on 2026-10-11 (version `0547fa5f`); the middleware falls back to an in-memory window if the binding is ever absent. |
| `triggers.crons` | `*/15 * * * *` (the reconciler: stuck webhooks, stale connections, expired Hosted Link sessions) and `0 3 * * *` (daily at 03:00 UTC: Plaid Item removal dispatch). Both are handled by `worker/src/cron.ts`, which branches on `controller.cron` (D-04, D-13). |
| `queues` | Producer binding `JOBS` → `resspark-jobs`. The main consumer has batch size 1, `max_retries: 5`, `retry_delay: 60` (the default delay when a job does not set its own; the consumer's backoff overrides it for transient vendor errors), concurrency 3, and dead-letter queue `resspark-jobs-dlq` (D-03). A second consumer reads `resspark-jobs-dlq` (batch size 10, `max_retries: 0`) so `jobs/index.ts` can record each dead-lettered job as `dead` in the ledger or as a `job.dead_lettered` event. Both queues were created with `wrangler queues create` on 2026-10-11. |
| `observability.logs.invocation_logs` | `false`: the platform's own per-request log records the URL, which would store `/c/<token>` (RESEARCH Pitfall 1, PLAT-08). `console.log` output from `logger.ts` is still collected. |

## Notes

- Deploy with `pnpm -C app run deploy`. Bare `pnpm deploy` is pnpm's workspace-deploy built-in and fails with `ERR_PNPM_NOTHING_TO_DEPLOY`.
- `app/worker/tsconfig.json` is the matching TypeScript project (`types: ["../worker-configuration.d.ts", "node"]`, `lib: ["ES2022"]`, no DOM) and is referenced from `app/tsconfig.json` so `tsc -b` covers the Worker.

## `send_email`

`[{ "name": "EMAIL" }]`: the Cloudflare Email Service binding (Workers Paid). `worker/src/integrations/email/cloudflare-email.ts` sends every email through `env.EMAIL.send()`: client links, staff invites and password resets. The binding is unrestricted; the sender comes from the `EMAIL_FROM` var, and the domain must be onboarded in the dashboard (see `cloudflare-email.md` § Setup). It replaced Resend on 2026-10-11.
