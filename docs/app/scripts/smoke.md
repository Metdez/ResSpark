# `app/scripts/smoke.mjs`

Node (≥22 `fetch`) script that proves a deployed ResSpark URL serves the SPA and the API from one Worker (PLAT-01). Usage: `node app/scripts/smoke.mjs <baseUrl> [--auth]`, or `pnpm -C app run smoke:auth <baseUrl> --auth`, which loads the env files the `--auth` checks need without naming them in a shell command.

| Lines | What it does |
|-------|--------------|
| 3-8 | Parses argv: the first non-flag argument is the base URL; missing → usage line on stderr and exit 1. |
| 9-10 | Strips a trailing slash; `--auth` enables checks marked `auth: true`. |
| 12 | `isObject` guard, same shape as the SPA's. |
| 14-18 | `expectJson(res, status, test)`: asserts the status, parses JSON, and runs a predicate on the body; throws a one-line reason otherwise. |
| 20-21 | `isNotFoundEnvelope`: body is `{ error: { code: 'not_found', … } }`. |
| 23-43 | `staffToken()` (Plan 06): reads `SUPABASE_URL ?? VITE_SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY ?? VITE_SUPABASE_PUBLISHABLE_KEY`, `DEMO_STAFF_EMAIL`, and `DEMO_STAFF_PASSWORD` from `process.env`; fails with a one-line reason naming the variables (never their values) when any is missing; signs in once with `POST {url}/auth/v1/token?grant_type=password` and the publishable key in the `apikey` header; caches the access token for the other checks. The token is never printed. |
| 44-46 | `session(init)`: a fetch to `<base>/api/admin/session`; the `signed_in` body. |
| 47-53 | `lookupFixture(headers)` (Plan 02-03): `POST <base>/api/admin/lookup` with `{ type: 'phone', value: '(555)010-0001' }`, the phone the fixture cases 900001 and 900002 share. |
| 55-62 | Plan 07 helpers: `expectPrivacyHeaders(res)` asserts `Cache-Control` contains `no-store`, `Referrer-Policy: no-referrer` and `X-Robots-Tag: noindex`; `invalidLink()` fetches `/c/not-a-valid-token` without following redirects. |
| 64-105 | `withProbeLink(body)` (`--auth`, Plans 07 and 02-07): needs `SUPABASE_URL`, `SUPABASE_SECRET_KEY` and `CLIENT_LINK_HMAC_KEY`. Dynamically imports `@supabase/supabase-js` (so the public checks stay dependency-free) and `node:crypto`. Re-finds the fixed probe case (Logics id `999999001`, the same fixture `requests-live.test.ts` uses, because events make cases undeletable) with `case_confirm_logics`, creates a one-item request with `request_create`, and sends it with `request_send` to get a real `client_links` row. Mints the token exactly like `worker/src/auth/client-link.ts` (HMAC-SHA256 over link id bytes plus big-endian `version`, base64url of id plus MAC) and passes `{ db, link, token }` to `body`. The `finally` block deletes the probe request, which cascades to its items, link, and `client_sessions` row. The token and RPC error details are never printed. |
| 107-122 | `linkExchange()` (Plan 07): requests `/c/<token>` on the deployed Worker and asserts 302 to `/c/`, a cookie with `rs_client=`, `HttpOnly`, `Secure`, `SameSite=Lax`, `Max-Age=86400` and without the token, the three privacy headers, and `opened_at` still `null`. |
| 124-154 | `clientPortal()` (Plan 02-07, PORT-01/02/05 deployed proof): exchanges the probe token for the `rs_client` cookie, then calls `/api/c/*` with the cookie and `X-Requested-With: ResSpark`. `GET /state` must be 200 with the privacy headers, `firm_name` `ValorTax`, `opened_at` `null`, one step, and no `request_id`, and must leave `opened_at` unset in the database. Two `POST /start` calls must return the same string `opened_at`, and the link row must then have it. `POST /heartbeat` with `{ last_step: 'smoke', user_agent_class: 'desktop' }` must return `{ ok: true }` and leave a `client_sessions` row with `last_step` `smoke`. `linkRow(db, id)` reads a link's `opened_at`. The cookie is never printed. The probe is deleted afterwards, so the count of opened links is unchanged across a run. |
| 156-192 | `requestSend()` (`--auth`, Plan 02-04, fake mode only): signs in as staff, refuses to run unless `GET /api/admin/integrations/logics` reports `fake`, confirms fixture case 900001, creates a "Documents only" draft from the seeded template, and sends it to the fixture contact (`jordan.rivera@example.com`, `(555) 010-0001`). It asserts the returned URL is `<base>/c/<64-char token>` at version 1, that opening it returns 302, that `POST .../copied` records the copy, and that `POST .../email` returns `ok: true` or `not_configured`. The `finally` block deletes the probe request with the service key, which cascades to its items and link, so the staff list stays clean. Failure messages name the method and path with the id masked as `:id`. The URL and token are never printed. |
| 194-244 | `checks` — the array later plans append to. `/admin` → 200, `text/html`, body contains `<div id="root"`; `/api/config` → 200 with string `app_env` and boolean `logics_write_enabled`; `/webhooks/smoke-probe` and `/api/nope` → 404 JSON `not_found` from the Worker (never `index.html`); `/c/ 404 html` → 404 `text/html` with the invalid-link heading; `/c/ headers` → the privacy headers on that 404; `/c/ spa` → `/c/` is 200 with `<div id="root"` and the privacy headers. |
| 245-261 | Plan 02-07 client-portal checks (PORT-06 deployed proof), no cookie and no `--auth`: `/api/c 401 no_session` expects `GET /api/c/state` to return 401 JSON with `error.code === 'no_session'` and the three privacy headers; `/api/c start 401` posts `/api/c/start` with `X-Requested-With: ResSpark` but no cookie and expects the same. Neither can open a link, so the count of opened `client_links` is unchanged across a run. |
| 262-263 | `auth /c/ exchange` runs `linkExchange` (deployed proof of D-18); `auth /api/c portal` runs `clientPortal`. |
| 264-288 | `--auth` staff checks (PLAT-04/PLAT-07 on the deployed Worker): `auth signed_in` posts `{ event: 'signed_in' }` with the bearer and expects 200 `ok: true` with a numeric `event_id` (one real `staff.signed_in` row per run); `auth session` expects `GET` 200 with a string `firm_id`; `auth 401 without token` expects 401 `error.code === 'unauthorized'`. A failure message can include the response body, which never contains the token. |
| 289-321 | Plan 02-03 lookup checks (LOOK-01 deployed proof): `auth integrations status` expects `GET /api/admin/integrations/logics` 200 with `mode` `fake` or `live`; `auth lookup fixture` expects the fixture-phone lookup 200 with a `results` array, and exactly 2 results when `mode` is `fake` (in `live` the fixture phone is not a real case, so the count is not pinned); `lookup 401 without token` runs in every mode and expects 401 `unauthorized`. The lookup check never prints the response body. Between them, `auth request send` runs `requestSend` (REQ-01/02 deployed proof). |
| 323-334 | Runs each applicable check, prints `ok <name>` or `FAIL <name>: <reason>`, exits 1 if any failed. |

## Notes

- Run from the repo root after `pnpm -C app run deploy`; the Plan 03 acceptance command is `node app/scripts/smoke.mjs "$(grep -oE 'https://[a-z0-9.-]+\.workers\.dev' docs/app/README.md | head -1)"`.
- Checks are independent; one failure does not stop the others, so the output lists every broken surface.
