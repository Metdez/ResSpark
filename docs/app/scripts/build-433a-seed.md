# `app/scripts/build-433a-seed.mjs`

Generates `supabase/migrations/0009_433a_seed.sql`, the reference rows Phase 7 reads:
`county_fips_map` (Census FIPS → the IRS housing table's own county text), `plaid_category_map` (every
Plaid PFC category → a 433-A line or an exclusion) and `truv_deduction_map` (pay-stub deductions → a
433-A line). The tables come from migration 0008; the line rules live in `lib/433a-mapping-rules.mjs`.
Node ESM, no dependencies. The output has no timestamps, so the same inputs give the same bytes.

## Inputs

Public files, downloaded into their own empty directory (never a tracked path) and read as data:

- Census 2025 Gazetteer counties:
  `https://www2.census.gov/geo/docs/maps-data/data/gazetteer/2025_Gazetteer/2025_Gaz_counties_national.zip`.
  Extract with `tar -xf` (on Git Bash use the Windows `tar.exe`, which reads zip files). Pipe-delimited,
  3,222 rows, header `USPS|GEOID|…|NAME|…`, includes Connecticut planning regions 09110-09190.
  Do not use `national_county2020.txt`: it still lists the old Connecticut counties.
- Plaid PFC taxonomy: `https://plaid.com/documents/pfc-taxonomy-all.csv`. Columns `PFCv2 Primary,
  PFCv2 Detailed, PFCv2 Description, PFCv1 Primary, PFCv1 Detailed, PFCv1 Description`; row 2 is a
  free-text note; descriptions contain quoted commas.
- Live tables through `lib/supabase-cli.mjs`: `state_aliases`, `county_suffixes`,
  `SELECT DISTINCT state, county, normalized_county FROM public.housing_utilities_standards`, and the
  `case_financial_data` column names (every mapped column must exist).

## Usage

```
node app/scripts/build-433a-seed.mjs --gazetteer <dir>/2025_Gaz_counties_national.txt --pfc <dir>/pfc-taxonomy-all.csv [--out <file>]
```

`--out` defaults to `supabase/migrations/0009_433a_seed.sql`. It prints the counts. It exits 1 with a
list when any county fails to resolve, the PFC counts change, or a mapped column is unknown.

## Code walkthrough

| Part | What it does |
|------|--------------|
| Argument parsing | `flag()` reads `--gazetteer` and `--pfc` (both required) and `--out`. A flag without a value throws. |
| `sqlText` | Turns a value into an SQL literal: `NULL`, a bare number (Truv `priority`), or single-quoted text with `'` doubled. Every text from a downloaded file goes through it. |
| `byKey`, `fail` | Plain string sort by one key (no locale), and print-a-list-then-exit-1. |
| Live reference tables | Loads state aliases, county suffixes (longest first), the `case_financial_data` column names and the distinct housing counties. |
| `normalize` | The same rules as `public.normalize_county_name`: lowercase, trim, strip the longest matching suffix, trim. |
| `housingByKey` | `(state, normalized_county)` → the first housing row (rows are ordered by state, county). |
| `readGazetteer` | Splits lines and finds `USPS`, `GEOID`, `NAME` by header name. |
| `buildCounties` | For each Gazetteer row: GEOID must match `^\d{5}$`; the state comes from `state_aliases` by the lowercased USPS code, else `USPS_EXTRA`. Rows with no state, or a state with no housing rows, are skipped and listed. Then an exact match on the normalized name; failing that, the `COUNTY_OVERRIDES` entry, which must be the exact text of a housing county in that state. Anything else is a failure. After the loop it adds the eight `CT_OLD_COUNTIES` rows with `county` NULL. Any failure exits 1 with the list. It also lists housing rows that no FIPS points at. |
| `readCsv` | A small RFC 4180 reader: quoted fields, doubled quotes, CRLF or LF, a leading BOM dropped. |
| `ruleFor` | The first `PFC_RULES` entry whose exact name or `PREFIX_*` pattern matches, else `pfcDefault(primary)`. |
| `buildPfc` | Finds the four columns by header name. Collects distinct v2 detailed names (with the v2 primary), then v1 detailed names not already seen (taxonomy `v1`, v1 primary). Names must be upper-case letters, digits and `_`, which drops the note row and blank cells. Exits 1 unless the counts are 127 and 3 ("Plaid's taxonomy changed; review PFC_RULES"). Assigns each name through `ruleFor` and checks that every income/expense row has a column. Sorted by name. |
| Column check | Every `canonical_column` in the Plaid rows and `TRUV_ROWS` must be a real `case_financial_data` column. |
| Emit | Header (`Generated by …`, input basenames, the re-apply recipe), `BEGIN`, then three upserts: `plaid_category_map` (`ON CONFLICT (pfc_detailed)`), `truv_deduction_map` (`ON CONFLICT (truv_category, name_pattern)`), `county_fips_map` sorted by FIPS (`ON CONFLICT (county_fips)`); the skipped and unmapped county lists as comments; `COMMIT`. |

## County matching rules

Matching is exact on the normalized name plus the explicit overrides. There is no fuzzy matching, so
an accepted county always hits the standards tables. The live check after applying:
`select count(*) from public.county_fips_map where county is not null and public.standards_housing_amount(state, county, 1) is null` must be 0.

## Result on 2026-10-11

- Counties: 3,230 rows (3,216 exact, 6 overridden, 8 old Connecticut), 0 skipped (Puerto Rico maps
  through `USPS_EXTRA`), one IRS row with no FIPS: `Bedford city, Virginia` (merged into Bedford
  County in 2013).
- Plaid: 130 rows (127 v2 + 3 v1: `INCOME_WAGES`, `INCOME_OTHER_INCOME`,
  `TRANSFER_IN_CASH_ADVANCES_AND_LOANS`): 9 income, 15 expense, 25 exclude, 81 informational.
- Truv: 15 rows.
- The file is about 222 KB and 3,406 lines. The Management API accepted it in one apply.

## Regenerate and re-apply

1. Run the generator with the same or newer inputs.
2. `node app/scripts/db-migrate.mjs --query "DELETE FROM public.app_migrations WHERE name = '0009_433a_seed'"`
3. `node app/scripts/db-migrate.mjs`

Every statement is an upsert, so re-applying is safe. A rule removed from `TRUV_ROWS` is not deleted
from the live table by a re-apply; delete it by hand. The generated file is exempt from the 500-line
limit and has no companion doc of its own; this page covers it.
