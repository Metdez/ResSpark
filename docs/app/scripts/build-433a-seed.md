# `app/scripts/build-433a-seed.mjs`

Generates `supabase/migrations/0009_433a_seed.sql`, the reference rows Phase 7 reads:
`county_fips_map` (Census FIPS → the IRS housing table's own county text). The tables come from
migration 0008. Node ESM, no dependencies. The output has no timestamps, so the same inputs give the
same bytes.

## Inputs

Public files, downloaded into their own empty directory (never a tracked path) and read as data:

- Census 2025 Gazetteer counties:
  `https://www2.census.gov/geo/docs/maps-data/data/gazetteer/2025_Gazetteer/2025_Gaz_counties_national.zip`.
  Extract with `tar -xf` (on Git Bash use the Windows `tar.exe`, which reads zip files). Pipe-delimited,
  3,222 rows, header `USPS|GEOID|…|NAME|…`, includes Connecticut planning regions 09110-09190.
  Do not use `national_county2020.txt`: it still lists the old Connecticut counties.
- Live tables through `lib/supabase-cli.mjs`: `state_aliases`, `county_suffixes`, and
  `SELECT DISTINCT state, county, normalized_county FROM public.housing_utilities_standards`.

## Usage

```
node app/scripts/build-433a-seed.mjs --gazetteer <dir>/2025_Gaz_counties_national.txt [--out <file>]
```

`--out` defaults to `supabase/migrations/0009_433a_seed.sql`. It prints the counts and exits 1 with a
list when any county fails to resolve.

## Code walkthrough

| Part | What it does |
|------|--------------|
| Argument parsing | `flag()` reads `--gazetteer` (required) and `--out`. A flag without a value throws. |
| `sqlText` | Turns a value into an SQL literal: `NULL`, or single-quoted with `'` doubled. Every text from a downloaded file goes through it. |
| Live reference tables | Loads state aliases, county suffixes (longest first) and the distinct housing counties. |
| `normalize` | The same rules as `public.normalize_county_name`: lowercase, trim, strip the longest matching suffix, trim. |
| `housingByKey` | `(state, normalized_county)` → the first housing row (rows are ordered by state, county). |
| `readGazetteer` | Splits lines and finds `USPS`, `GEOID`, `NAME` by header name. |
| `buildCounties` | For each Gazetteer row: GEOID must match `^\d{5}$`; the state comes from `state_aliases` by the lowercased USPS code, else `USPS_EXTRA`. Rows with no state, or a state with no housing rows, are skipped and listed. Then an exact match on the normalized name; failing that, the `COUNTY_OVERRIDES` entry, which must be the exact text of a housing county in that state. Anything else is a failure. After the loop it adds the eight `CT_OLD_COUNTIES` rows with `county` NULL. Any failure exits 1 with the list. It also lists housing rows that no FIPS points at. |
| Emit | Header (`Generated by …`, input basenames, the re-apply recipe), `BEGIN`, one upsert sorted by FIPS (`ON CONFLICT (county_fips) DO UPDATE`), the skipped and unmapped lists as comments, `COMMIT`. |

## Matching rules

Matching is exact on the normalized name plus the explicit overrides. There is no fuzzy matching, so
an accepted county always hits the standards tables. The live check after applying:
`select count(*) from public.county_fips_map where county is not null and public.standards_housing_amount(state, county, 1) is null` must be 0.

Result on 2026-10-11: 3,230 rows (3,216 exact, 6 overridden, 8 old Connecticut), 0 skipped
(Puerto Rico maps through `USPS_EXTRA`), one IRS row with no FIPS: `Bedford city, Virginia`
(merged into Bedford County in 2013).

## Regenerate and re-apply

1. Run the generator with the same or newer inputs.
2. `node app/scripts/db-migrate.mjs --query "DELETE FROM public.app_migrations WHERE name = '0009_433a_seed'"`
3. `node app/scripts/db-migrate.mjs`

Every statement is an upsert, so re-applying is safe. The generated file is exempt from the 500-line
limit and has no companion doc of its own; this page covers it.
