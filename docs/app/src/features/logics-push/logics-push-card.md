# `app/src/features/logics-push/logics-push-card.tsx`

The `Push to Logics` card on `/admin/requests/$requestId`, mounted below the review panel (Phase 5 D-09, PUSH-01, PUSH-02, PUSH-04).

| Part | What it does |
|------|--------------|
| `Heading` | `Push to Logics`, 20 px semibold, the same heading style as the review panel. |
| `Row` | A `PushableDoc` plus its item label, its ledger rows, `sent` (one of its latest rows is `sent`), and `disabled`. |
| `LogicsPushCard({ requestId, caseId })` | Reads `useReview(requestId)` (the same cached query as the review panel), `useLedger(requestId)`, `useWorksheets(caseId)` (Plan 07-06), and the signed-in staff name from `useSession()`. While the review loads: three 40 px `Skeleton` rows; on a review error: the generic error line (the review panel above shows the full alert with Retry). |
| Pushable rule | Only documents with `status 'ready'` under items with `status 'approved'`. Rejected files and files of items not yet approved never appear. |
| `toRow(doc, itemLabel)` | Builds a `Row` from a document and its group label. It attaches the latest ledger rows and the `pushPlan`, and sets `sent` and `disabled`. Request documents and worksheets share it. |
| 433-A worksheets (D-16) | When `useWorksheets(caseId).data.request_id === requestId` (this is the case's most recent request that is not revoked), the case's generated worksheets are added as `application/pdf` rows under the group `433-A worksheets`, after the item groups. They use the same row component, checkbox, size, plan label and ledger chips, and the same push selection and sheet. On any other request of the case the group does not appear, so a worksheet is offered in one place only. A worksheet alone is enough to replace the empty block. |
| Empty block | When nothing is pushable: the inherited empty block (48 px icon, `Nothing approved yet`, `Approve an item and its files appear here.`). |
| `disabled` | A row cannot be selected when its plan is `manual`, when a row is `queued`/`sending`, or when one of its latest rows is `sent` or `unknown`. There is no `Push again`: a `sent` fingerprint always ends in 409 `already_pushed` (partial unique index `logics_pushes_fingerprint_live`), and a second push of an `unknown` file could duplicate it in Logics, so `unknown` goes only through the two-action resolve dialog (D-04). A `failed` row can be selected and pushed fresh. |
| Ledger error | A destructive line `Couldn't load what was already pushed.` with a `Retry` link; the push button stays disabled until the ledger loads, because the duplicate guard needs it. |
| Groups | Rows are grouped under their item label (14 px muted heading). |
| Select all | One house `Checkbox` (`id logics-push-select-all`) with the visible `Label` `Select all`, above the groups (Oct 12 call: "click all, boom, send"). `checked` is true when every enabled row is selected, `indeterminate` (`aria-checked="mixed"`, shown with a half-tone fill) when some are, false otherwise; it is disabled when no row can be pushed. Checking it selects every enabled row; unchecking clears the selection. Disabled rows (sent, in flight, unknown, manual) are never selected. |
| Push button | Right-aligned. Label `Push to Logics` only when the ledger says `mode 'live'`; otherwise `Push to Logics (simulated)`. Disabled with nothing selected. It opens the confirmation sheet with the selected rows. |
| `DocRow` | A 40 px dense row: `Checkbox` (`aria-label` `Select {name}`), the name (`title` holds the full name), `sizeLabel`, the plan label (muted, or destructive for `manual`), one `PushChip` per ledger row, one muted `Simulated` badge when any row is `mode 'fake'`, and for `sent` rows the muted text `Already pushed`. |
| Sheet and dialog | `pushing` holds the rows chosen when the button was clicked and mounts `<PushSheet>` (mode from the ledger, agent from the session); its `onDone` closes it and clears the selection. `resolving` holds the clicked ledger row and feeds `<ResolveUnknownDialog>` (keyed by row id so the input resets), with `allowMarkSent` only for `unknown`. |
| `PushChip` | `part k of n` when `part_count > 1`; then the state badge. `unknown` is a button labelled `Needs your decision` that opens the resolution dialog. `sent` adds `#<CaseDocumentID>`, or `Confirmed by staff` when staff marked it sent without an id. `failed` adds the `error_detail` copy, then either `Compress it outside ResSpark and re-upload to the item` (manual compression) or a `Re-send` link that opens the dialog in resend-only mode. |

## Safety rules

- There is no retry-all, auto-retry, or background re-send control. The only ways out of `unknown` are the two staff decisions in the dialog (D-04).
- The `Simulated` badge and the `(simulated)` label cannot be hidden or dismissed (D-10, Pitfall 7).

## Tests

`logics-push-card.test.tsx` (`web` project; `useReview`, `useSession`, `./api` and `sonner` mocked; `useQuery` spied): empty block; two ready PDFs of an approved item listed with `Sends as 1 file` and `Will split into about 2 parts`, rejected and not-approved files absent, the button disabled until a checkbox is ticked; `Push to Logics` in live mode; the ledger query uses `pollInterval`; a fake `sent` row shows `Sent`, `#128346`, `Simulated`, `Already pushed`, a disabled checkbox and no `Push again` control; an `unknown` row is disabled, has no `Push again` and no `Already pushed`, and offers only `Needs your decision`; a non-manual `failed` row stays selectable; `unknown` renders as the `Needs your decision` button and a two-part document shows `part 1 of 2` / `part 2 of 2` with the spinner on `sending`; a manual-compression failure shows its copy and no `Re-send`; with worksheets for `r1`, a `433-A worksheets` heading, a `Select <file name>` checkbox, `Sends as 1 file`, and the sheet opened with the worksheet (`listWorksheets` called with the case id); with `request_id` of another request, no group; a worksheet alone replaces the empty block; selecting a file and clicking the button opens the sheet with that file's comment; clicking `Needs your decision` opens the dialog. Select all (`LogicsPushCard select all`): with a sent row, a `text/plain` (manual) row, one enabled PDF and a worksheet, clicking it checks exactly the enabled rows (`aria-checked`), enables the button, and the sheet lists only those files; a partial selection reads `mixed`, a click then checks all and another clears everything and disables the button; with nothing pushable the checkbox is disabled.
