# `app/src/routes/admin/_shell/cases/$caseId/433a.tsx`

The file route for `/admin/cases/$caseId/433a` (D-14), inside the authenticated `_shell` layout, so the sign-in guard and sidebar apply.

| Part | What it does |
|------|--------------|
| `Route` | `createFileRoute('/admin/_shell/cases/$caseId/433a')` with `FinancialsRoute` as the component. The TanStack router plugin adds it to `routeTree.gen.ts` on build (never hand-edit that file). |
| `FinancialsRoute` | Reads `caseId` from the typed params and renders the admin page chrome (`Header` with `Search`, `ThemeSwitch`, `ProfileDropdown`, then `Main`, the same as the request route) around `FinancialsPage`. |

## Notes

- The chrome lives here, not in the feature, so `FinancialsPage` renders in tests without the sidebar, search and router providers.
- Staff reach the route from the request page header link `433-A worksheet` (`docs/app/src/features/requests/request-page.md`).
- The case id travels in the path only; no amount or value is ever put in a route param or query string (T-07-40).
