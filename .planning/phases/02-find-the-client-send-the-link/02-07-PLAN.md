## Phase Goal

**As a** ValorTax case manager, **I want to** type a phone number, case ID, or email, confirm the matching Logics case, and copy a request link that the client opens on a phone, **so that** I can get a client started in under a minute while still on the call.

<objective>
Give the client side its three Worker routes on top of the Phase 1 cookie session: `GET /api/c/state` (firm, agent, step list), `POST /api/c/start` (the explicit "opened" transition through `request_open`), and `POST /api/c/heartbeat` (the `client_sessions` upsert Phase 3's mirror view reads), with the `clientSession` middleware that never trusts ids from the request, CSRF header enforcement, per-link rate limiting, and the privacy headers on every `/api/c/*` response.

Purpose: PORT-01..06 server behavior — the half of the client experience that must be right before any screen exists.
Output: `middleware/client-session.ts`, `routes/client-portal.ts`, `db/portal.ts`, `allowInWindow` export, index wiring, tests, docs, redeploy.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-33 | Elevation of privilege | IDOR via body/query request or link ids on `/api/c/*` (C3) | critical | mitigate | `clientSession` resolves identity only from the signed cookie; routes never read ids from the request; test posts foreign ids and asserts the cookie's link was used |
| T-02-34 | Spoofing | CSRF on the cookie-authenticated POSTs | medium | mitigate | `SameSite=Lax` cookie (Phase 1) + `X-Requested-With: ResSpark` required on every POST (403 `bad_origin`) |
| T-02-35 | Spoofing | forged or replayed `rs_client` cookie | high | mitigate | Hono signed cookie verified with the derived `cookieSecret`; payload `exp` enforced; link row re-checked (revoked/expired) on every call |
| T-02-36 | Denial of service | heartbeat flood per link | medium | mitigate | `allowInWindow('hb:<link>', 10, 60 s)` → 429; body size caps (64/200 chars) |
| T-02-37 | Information disclosure | contact or identifier leakage in the portal DTO (C2, C3) | high | mitigate | Allow-listed DTO built from an explicit field list; test asserts the exact key set and the absence of `email`/`phone`/ids |
| T-02-38 | Tampering | link marked opened by a scanner or the cookie exchange (C2) | high | mitigate | Only `POST /api/c/start` (header-gated) calls `request_open`; `client-link.ts` still never touches `opened_at`; deployed `--query` asserts 0 opened rows after smoke |
| T-02-39 | Information disclosure | 401 variants revealing why a session failed | medium | mitigate | One `no_session` code and byte-identical body for missing/forged/expired/revoked; test compares the bodies |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installed; gate not triggered |
