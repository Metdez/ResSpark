## Phase Goal

**As a** ValorTax case manager, **I want to** type a phone number, case ID, or email, confirm the matching Logics case, and copy a request link that the client opens on a phone, **so that** I can get a client started in under a minute while still on the call.

<objective>
Expose the request lifecycle as Worker routes behind `staffAuth`: templates and draft creation from a template, the send step that validates the contact (shared Zod), re-fetches the case from Logics (stale-match refusal), calls `request_send`, and mints the copyable URL with the Phase 1 primitives; regenerate/revoke; best-effort email through Resend; the SMS-consent event. Redeploy so the deployed Worker can produce a real client link.

Purpose: REQ-01..05 and LOOK-04's send-time re-fetch become real API behavior; Plan 05's SPA and Plan 08's end-to-end smoke build on these exact contracts.
Output: `db/requests.ts`, `routes/admin-requests.ts`, `routes/admin-request-actions.ts`, `integrations/email/resend.ts`, tests, docs, redeploy.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Worker `/api/admin/requests/*` | staff bearer JWT; bodies (contact fields, `keep_flagged`, items) are untrusted |
| Worker → Logics `Case/CaseInfo` | send-time re-read of the case |
| Worker → Resend (`api.resend.com`) | client email address and the link leave the platform |
| Worker → `client_links` ↔ `/c/<token>` | the minted URL is the client's credential |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-18 | Tampering | wrong-client send after the Logics record changed (C8, LOOK-04) | critical | mitigate | Send re-fetches `Case/CaseInfo` and refuses with `case_changed` on any name/contact difference or missing case; cached snapshot is never the send-time source; tests cover changed name and missing case |
| T-02-19 | Tampering | link emailed/sent to a typo'd or non-Logics address (M2, C8) | high | mitigate | `checkContact` server-side (400 `contact_invalid`), `did you mean` + differs-from-Logics gate (409 `contact_flagged`) requiring an explicit `keep_flagged`, override recorded in the `request.sent` payload |
| T-02-20 | Spoofing | email recipient supplied by the request body | high | mitigate | The email handler reads no body; recipient is the stored `contact_email`; test posts `to: attacker@…` and asserts the stored address was used |
| T-02-21 | Information disclosure | token/URL persisted or logged | high | mitigate | URL re-derived per response via `mintLinkToken` (D-17); never written to a table or event payload; logger allowlist excludes bodies |
| T-02-22 | Tampering | HTML/header injection through firm/agent names in the email | medium | mitigate | `escapeHtml` on every interpolation in `html`; Resend takes JSON so no raw header line is constructed; test asserts the escaped form |
