**As a** tax-resolution client, **I want to** confirm my address and sign my forms on my phone from the same link, **so that** I am done without zooming, scrolling, or waiting on an email.

<objective>

| Worker → Smarty (`us-autocomplete-pro`, `us-street`) | outbound calls carrying the secret key pair in a Basic header |
| Worker (`service_role`) → `case_confirm_address` | bypasses RLS by design; the RPC re-checks link → request → item |
| developer shell → Management API / `wrangler secret put` | migration and secrets run as the operator |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Information disclosure | Smarty keys leaking to the browser or logs | high | mitigate | keys only in Worker secrets; Basic header, never query-string auth; no `VITE_*` copy; client never calls Smarty (D-03); the allowlisted logger never logs URLs or headers |
| T-06-02 | Denial of service / cost | Smarty credit burn through the suggest proxy | medium | mitigate | cookie session required; `allowInWindow('addr:'+linkId, 30, 60_000)` on both routes; 3-character minimum and 32-character cap; SPA 250 ms debounce (Plan 03) |
| T-06-03 | Tampering / Elevation | writing an address onto another client's case | high | mitigate | `findSessionItem` scopes by the session's request; the RPC re-selects the link and the item `FOR UPDATE` with `request_id` and `kind = 'address'` and refuses revoked or expired links; `approved` items are frozen |
| T-06-04 | Information disclosure | street text in events, logs, or heartbeat | medium | mitigate | event payload is `{ source, verified, county_fips, rdi }` only (live test asserts no street or ZIP text); county/RDI are not returned to the client |
