## Phase Goal

**As a** tax-resolution client, **I want to** confirm my address and sign my forms on my phone from the same link, **so that** I am done without zooming, scrolling, or waiting on an email.

<objective>
Ship the e-sign start path on the server as one proven slice: the shared template keys and ESIGN consent text, the DocuSeal REST client, the lazy submission (row before URL, reuse, retry after decline or expiry), and the consent-gated `POST /api/c/items/:itemId/signature/start`. Prove it live with DocuSeal stubbed: cookie → start refused (409, no vendor call) → `esign` consent → start → `GET /templates/{id}` + `POST /submissions` → a pending `docuseal`/`signature` connection holding the submission id and slug → a second start reuses the row through `GET /submitters/{id}`.

Purpose: SIGN-01's provider integration and SIGN-03's consent record exist before any UI; Plans 04–07 build the webhook, the admin mapping, the signing page, and the staff card on these contracts.
Output: `lib/{esign-templates,consent-text}.ts`, `integrations/esign/{docuseal,start}.ts`, `db/esign-settings.ts`, `routes/c-signature.ts` mounted; consent kind widened; Phase 4 union types widened; DocuSeal fixtures; live and unit tests; companion docs.
</objective>
