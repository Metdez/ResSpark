Purpose: Plans 08 and 10 implement exactly one signature variant and one sign flip from these fixtures; guessing either would reject every real connect or invert every amount. Every other Phase 8 plan is independent of this one.
Output: `08-SPIKE-TELLER.md` findings, three sandbox fixtures, the uploaded certificate id (not a secret), and no leftover Cloudflare resources.
</objective>

<interfaces>
Teller facts (08-RESEARCH § Pattern 4, § Code Examples; teller.io/docs fetched 2026-10-11):
- Base `https://api.teller.io`; access token is the Basic-auth user with an empty password; mTLS optional in sandbox, required in development/production.
- `GET /accounts` → `[{ id, enrollment_id, institution { id, name }, last_four, name, type, subtype, status, currency, links }]`; `GET /accounts/:id/transactions?start_date=&end_date=` (inclusive ISO dates; first call can time out — retry once); `amount` is a signed string; `status` posted|pending; `DELETE /accounts` → 204 ends the enrollment.
- Connect: `<script src="https://cdn.teller.io/connect/connect.js">`, `TellerConnect.setup({ applicationId, environment, products: ['transactions'], nonce, onSuccess(enrollment) })` → `.open()`; `onSuccess` gives `{ accessToken, user: { id }, enrollment: { id, institution: { name } }, signatures: string[] }`; signed message documented as "ED25519 with a SHA-256 digest" over `nonce.accessToken.userId.enrollmentId.environment`; sandbox login `username` / `password`.
- Workers: `mtls_certificates: [{ binding: 'TELLER_CERT', certificate_id, remote: true }]`; upload with `wrangler mtls-certificate upload --cert <pem> --key <pem> --name <name>` (token needs "SSL and Certificates Edit"); Web Crypto supports `Ed25519` importKey/verify on Workers and Node 24.
- `pnpm -C app wrangler …` runs wrangler with the Cloudflare token from the repo `.env` (package script; never name env files in Bash).
</interfaces>
