## Phase Goal

**As a** ValorTax case manager, **I want to** nudge clients automatically, offer a cheaper second bank option, and run on a platform that meets security and vendor requirements, **so that** ResSpark can move from the demo to live ValorTax cases.

<objective>
Protect the client link with an identity check that is on by default (REM-04): before anything about the case is shown, the client confirms a date of birth (or the last four digits of the phone on file), compared against keyed digests taken from Logics at send time. Five wrong tries lock the link until staff regenerate it.

Purpose: a forwarded or leaked link is the platform's biggest client-side exposure (PITFALLS C2). The gate reuses the existing signed cookie (a `gate: 1, v` flag), so there is no new session store and no new secret.
Output: `auth/identity-gate.ts`, `db/gate.ts`, `requireGatePassed`, `POST /api/c/verify`, minimal gated state, send-time digests, fake-case DOBs, the client gate screen, live and unit tests, companion docs.
</objective>
