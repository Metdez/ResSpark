## Spacing Scale

Declared values (multiples of 4). Tailwind 4 default scale maps 1 unit = 4 px, so these are the stock utilities.

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Icon-to-label gap, badge vertical padding |
| sm | 8px | `2` | Gap between inline controls, table cell vertical padding, form field label-to-input |
| md | 16px | `4` | Default gap between fields and list rows; client page horizontal padding on phones |
| lg | 24px | `6` | Card padding, gap between form sections, sign-in card padding |
| xl | 32px | `8` | Admin page padding on `≥ 768 px`; gap between dashboard panels |
| 2xl | 48px | `12` | Empty-state icon size and vertical padding inside empty states |
| 3xl | 64px | `16` | Admin header height (`h-16`); top offset of the client content column on phones |

Exceptions (all multiples of 4):
- **12 px** (`3`): horizontal cell padding in dense admin tables and horizontal badge padding. Reason: 16 px wastes width across 7+ columns; 8 px lets adjacent values touch.
- **36 px** (`h-9`): SANDBOX banner height.
- **40 px** (`h-10`): dense table row height, default `Button` height (`size="default"`), input height.
- **44 px** (`h-11`): minimum tap target for every interactive element under `/c/*` (WCAG 2.2 AA, PORT-05). Applies to buttons, links styled as buttons, checkboxes' hit areas, and list rows.
- **256 px / 48 px**: sidebar expanded / collapsed (`sidebar.tsx` defaults, unchanged).
- **384 px** (`w-96`): sign-in card width. **480 px** (`max-w-[30rem]`): client content column max width.

## Typography

Exactly four sizes and two weights. Nothing else is permitted without amending this section.

| Role | Size | Weight | Line Height | Tailwind | Where |
|------|------|--------|-------------|----------|-------|
| Label | 14px | 400 (600 for table headers and the SANDBOX label) | 1.5 | `text-sm` | Admin table cells, badges, sidebar items, form labels, helper and footer text, toast body |
| Body | 16px | 400 | 1.5 | `text-base` | All client-side text (minimum size on `/c/*`), admin prose, dialog bodies, inputs |
| Heading | 20px | 600 | 1.25 | `text-xl font-semibold leading-tight` | Card titles, empty-state headings, dialog titles, client page section titles, firm name in the client header |
| Display | 24px | 600 | 1.25 | `text-2xl font-semibold leading-tight` | One per page: admin page title ("Dashboard"), sign-in title, client page title |

Rules:
- `font-medium` (500) and `font-bold` (700) are not used; search-and-replace them out of copied shadcn-admin feature files (the vendored `ui/*` files keep their internals).
- Client pages (`/c/*`): no text below 16 px, ever — including badges and helper text (use `text-base` there, overriding the Label role). Reason: seniors on phones (PORT-05, orchestrator note).
- Numbers in tables: `tabular-nums`, right-aligned. Money: `$1,234.56` via `Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })`. Dates: `Oct 10, 2026`; relative times (`2 h ago`) always carry the absolute timestamp in `title`.
- Sentence case for every heading, label, button, and menu item ("Sign in", not "Sign In"). All-caps only for the 7-letter word SANDBOX in the banner.
- Truncation: single-line labels in the sidebar, table cells, and the client header use `truncate` with the full text in `title`; body copy wraps.

| Info (new) | `--info` | Tailwind `sky-600` | `#0284c7` | "Opened" and "in progress" badges |

Accent (`--primary`) reserved for exactly:
1. The single primary `Button` on a screen ("Sign in"; later "Send link", "Start", "Approve").
2. The active sidebar item's icon and text (background stays `--sidebar-accent`, the 30% tone).
3. Text links inside body copy (`underline underline-offset-4`).
4. Checked state fill of checkbox, radio, and switch.
5. The app title in the sidebar header.

Not accent: table header text, badges, secondary buttons (`variant="outline"`), icons in cells, the banner. Interactive affordance comes from shape, underline, and hover tone, not from coloring everything navy.

Semantic tokens added to `theme.css` (`:root` and `.dark`), registered in `@theme inline` as `--color-success`, `--color-warning`, `--color-warning-foreground`, `--color-info`, `--color-brand`, `--color-brand-foreground`. Dark values: warning unchanged (amber-400 reads on dark), success `emerald-500`, info `sky-500`.

## Screens (Phase 1)

### S1 — `/admin/sign-in`
- Full-viewport `bg-muted/40` backdrop; SANDBOX banner at top (it is an admin page); centered `Card` 384 px wide, 24 px padding, `rounded-lg`, 1 px border, no shadow heavier than `shadow-sm`.
- Inside: app title (Heading, accent color) → Display title → subtitle (Label, muted) → form: Email (`type="email" autoComplete="username" inputMode="email"`), Password (`password-input.tsx`, `autoComplete="current-password"`), form-level error `Alert` slot above the button, full-width "Sign in" button (`h-10`).
- No social buttons, no "Forgot password", no "Sign up", no terms footer (stripped from `user-auth-form.tsx`).
- Submit on Enter; the button is the only accent element.
- Validation: Zod 4 schema; errors appear on blur and on submit, inline under the field in `text-destructive` 14 px; the field gets `aria-invalid`.
- Success: `POST /api/admin/session {event:'signed_in'}` then navigate to `search.redirect ?? '/admin'` with `replace: true`.

### S2 — Admin shell (`/admin/_shell/*`)
- Layout rows: SANDBOX banner (36 px, sticky, `z-50`, full width, above everything including the sidebar) → `SidebarProvider` → `AppSidebar` (256 / 48 px) + content column (`Header` 64 px sticky with `SidebarTrigger`, `Separator`, page title breadcrumb, right cluster `Search` → `ThemeSwitch` → `ProfileDropdown`; `Main` with 16 px padding on phones, 32 px at `≥ 768 px`).
- Sidebar header: `AppTitle` = 20 px Lucide `Zap`-style glyph slot + `VITE_APP_NAME` (accent). Groups per the inventory table. Footer: `NavUser` with `Avatar` initials, display name (Label 600), role (Label muted).
- Mobile (`< 768 px`): sidebar becomes a `Sheet`; the banner stays; header keeps the trigger, title, and profile only (search and theme move into the profile menu).
- Banner never hides on scroll, never collapses with the sidebar, has no close button, is not stored in any state; it renders whenever `/api/config.app_env !== 'production'`. While `/api/config` is loading, render the banner anyway (fail-safe: absence of proof is sandbox).

### S3 — `/admin` (empty dashboard)
- Display title "Dashboard"; one `Card` spanning the content width with a centered empty-state block (`min-h-60` = 240 px, `py-12`): Lucide `Inbox` 48 px in `text-muted-foreground`, Heading "Nothing to do yet", Body muted (copy above), no CTA (A-7). Nothing else on the page: no fake metrics, no placeholder charts, no `recharts` import (so the chunk is not loaded).

### S4 — Sign-out
- `ProfileDropdown` → "Sign out" → `SignOutDialog` → confirm → `POST /api/admin/session {event:'signed_out'}` (before `supabase.auth.signOut()`, D-16) → `signOut()` → navigate `/admin/sign-in` with `replace`. If the event POST fails, still sign out locally and show the generic error toast (never trap a user in a session).

### S5 — Client shell (`/c/*`) — **Inherited** layout for every Phase 2+ client screen

## Inherited conventions (Phases 2–8)

### Loading
- Route transitions: `navigation-progress.tsx` bar only; TanStack `defaultPendingMs: 300` so sub-300 ms loads show nothing.
- Lists and tables: `Skeleton` rows in the final layout (3 rows, same column widths), never a centered spinner.
- Buttons performing async work: disabled + 16 px `Loader2` + progressive label ("Signing in…", "Sending…"); the rest of the form stays enabled unless submission would double-fire.
- Initial auth check: the router's pending component is blank (white) — no flash of the sign-in page for signed-in users and no spinner for sub-300 ms resolves.

### Empty
- Centered block: 48 px muted Lucide icon → Heading → one-sentence Body (muted) → at most one primary CTA when an action exists. Always inside the container the data would fill, `min-h-60`.
- Zero / one / many: copy uses the real count ("1 request", "12 requests"); never "1 request(s)".

### Error
- Form-level: `Alert variant="destructive"` with `AlertTitle` (what happened) and `AlertDescription` (what to do). Field-level: inline text under the field. Async action outside a form: `toast.error` with the same two-part copy. Never both a toast and an alert for the same failure.
- API envelope `{ error: { code, message } }`: show `message` only when `code` is in the SPA's known-copy map; otherwise the generic staff copy. Clients never see `code`.
- 401 → redirect to sign-in; 403 → "You don't have access to this." inline; 404 → `features/errors` page; 5xx → generic copy + retry button where the action is idempotent.

### Dense admin tables (ERPNext-spirit, shadcn `Table` + TanStack Table 8.21)
- 14 px text, 40 px rows, header row `bg-muted` with 600 labels, `px-3 py-2` cells, sticky header, `hover:bg-muted/50` rows, no zebra striping, first column is the entity name (link styled, accent), status badge column uses the palette above, numeric columns right-aligned `tabular-nums`, timestamps as relative with absolute `title`, row actions in a trailing `DropdownMenu` (`MoreHorizontal`, tooltip "Actions"). Horizontal scroll beyond 7 columns; never shrink text to fit.

### Forms
- `Label` above input, 8 px gap; helper text 14 px muted below; required fields are the default and unmarked; optional fields say "(optional)" in the label. Submit button right-aligned on `≥ 640 px`, full-width below. Destructive actions never sit next to the primary action without a 16 px gap and an `outline` variant.

### Accessibility floor (WCAG 2.2 AA)
- `skip-to-main.tsx` first in tab order on admin pages; landmark elements (`<header>`, `<nav aria-label="Main">`, `<main id="main">`); visible focus (`outline-ring/50`) never removed; icon-only buttons have `aria-label` + `Tooltip`; status conveyed by text + color; `prefers-reduced-motion` disables `tw-animate-css` transitions (add `@media (prefers-reduced-motion: reduce) { * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; } }` to `index.css`); minimum contrast 4.5:1 for text, 3:1 for UI boundaries; client pages pass with 200 % browser zoom and 320 px width.
