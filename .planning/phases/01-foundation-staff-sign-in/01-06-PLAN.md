| Boundary | Description |
|----------|-------------|

| Worker → Supabase JWKS endpoint | public keys fetched over HTTPS and cached |
| browser localStorage | supabase-js session storage (XSS surface) |
| `?redirect=` search param | attacker-controlled navigation target |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-25 | Spoofing | forged or algorithm-confused JWT | critical | mitigate | `jose` `jwtVerify` against the project JWKS (ES256 only, F-3) with `issuer` + `audience` pinned; `auth.test.ts` proves a foreign-key token and a wrong-issuer token are 401 |
| T-01-26 | Elevation of privilege | cross-firm access via claims or body | high | mitigate | `staffAuth` cross-checks `app_metadata.firm_id` with `staff_profiles.firm_id` (403 on mismatch or missing profile); the session route ignores body fields other than `event`; unit test posts a foreign `firm_id` in the body and asserts it is ignored |
| T-01-27 | Information disclosure | session token in localStorage readable by XSS | medium | accept | supabase-js default and the only place the SPA holds the token; no third-party scripts are loaded (Plan 02 prohibition); a CSP arrives with the first third-party embed in Phase 4; the Worker is the authority on every request (Pitfall 7) |
| T-01-28 | Spoofing | open redirect through `?redirect=` | medium | mitigate | `safeRedirect()` accepts only `/admin…` paths (no scheme, no `//`); tested with four hostile inputs |
| T-01-29 | Repudiation | forged `signed_out` event for another user | low | accept | Requires that user's valid bearer token; `actor_id` is always the verified `sub` |
