## Phase Goal

**As a** ValorTax case manager, **I want to** review what clients upload from their phones and watch status update live, **so that** I can approve or reject each item without chasing anyone.

<objective>
Ship the upload tracer: the schema (`0004_uploads_review.sql` — documents columns, private bucket, `request_status()`, the review RPCs, the dashboard view), the Worker's storage module, and the two client routes that mint a signed upload token and finalize an upload with a magic-byte check. Prove it live against the real project with a test that mints, PUTs bytes straight to Storage, completes, and sees `documents.status = ready`, `request_items.status = submitted`, a `document.uploaded` event, and `requests.status = waiting_on_staff` — then prove the mismatch path deletes the object.

Purpose: every other Phase 3 plan (client sheet, staff review, dashboard, timeline) builds on this slice; `request_status()` is the single source of truth every RPC calls (D-06), and it must exist before any UI shows a status.
Output: migration applied and recorded; `storage/case-documents.ts`, `db/documents.ts`, `routes/c-uploads.ts` registered in `index.ts`; live tests `uploads.test.ts` and `request-status.test.ts`; `rls.test.ts` covers the new view; companion docs.
</objective>
