## Phase Goal

**As a** ValorTax case manager, **I want to** review what clients upload from their phones and watch status update live, **so that** I can approve or reject each item without chasing anyone.

<objective>
Turn the Phase 1 empty dashboard into the live request list: Phase 2's firm-scoped `GET /api/admin/requests` gains `?status=&q=` and reads `request_dashboard_v` (its response stays a superset of what `/admin/requests` already consumes), and a dense TanStack Table with status chips, text search, sortable columns, overdue badges, and a visibility-aware 5 s poll — so Andrew watches a request flip from "in progress" to "complete" within 10 seconds of the approve click.

Purpose: STAT-01 and STAT-02 (dashboard half). The endpoint path is D-07's; it lives in Phase 2's `admin-requests.ts` rather than a new route file because that path already exists there and two handlers for one path is exactly the bug a new file would invite.
Output: `db/dashboard.ts`, the extended `GET /` in `routes/admin-requests.ts`, `features/dashboard/*` replacing the empty dashboard, tests, docs.
</objective>
